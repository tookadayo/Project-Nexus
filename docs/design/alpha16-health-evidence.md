## ADD09 saved-source execution preview addition (source only)

The existing GET `/api/health/lifecycle-preview?revision=<uuid>` now appends a `BOUNDED_SAVED_SOURCE_SIMULATION` result. READ allows metadata/configuration comparison; existing ANALYZE permission additionally gates member-source evaluation. Current OAuth/guild/Bot authority, READ/Beta/privacy/tombstone checks, existing plan decisions and request-local authority expiry remain mandatory. The source reads run in a READ COMMITTED, READ ONLY transaction under the existing scope/privacy lock order. This deliberately avoids a repeatable-read snapshot acquired before waiting for a deletion's advisory lock. The fingerprint identifies the exact bounded source vector used, not a newly persisted or globally atomic ingestion snapshot; concurrent late observations can make a replay unavailable. No new endpoint, permission, collection, persisted snapshot, retained purpose or external call is introduced.

Only server-read saved observations are evaluated. The bounds are 25 recent eligible active participation episodes, 200 events per episode, 100 telemetry gaps, and 2,000 definition nodes/16 structural levels. One extra row detects each truncation. PRODUCTION context, completed guest/screening eligibility, existing detailed-retention cutoff, pending privacy deletion exclusions, selected analysis scope and current channel/parent visibility/collection restrictions are enforced. Event data is projected to the few scalar fields required by the evaluator; member identity, episode ID, actor, message content and source values are never returned. Missing/expired role observation, telemetry gaps, raw-source truncation, missing channel provenance and unavailable native observations remain unknown. Existing `activation.completed` projections cannot establish the visible-source provenance for a different revision and are withheld.

Activation reuses `evaluateCondition` over bounded original event/role clocks. Intervention evaluates conditions and trigger observations but cannot prove authenticated origin from the existing projection. Only an explicit false condition produces false eligibility; otherwise missing condition evidence, pending delay, unavailable/unobserved trigger or observed trigger with unproved origin produce separate UNKNOWN causes. In particular, an observed trigger yields `UNKNOWN_TRIGGER_ORIGIN`, never WOULD_SUGGEST/WOULD_REQUIRE_APPROVAL/WOULD_QUEUE. It does not call `interventionEligible` with that helper's default member origin and does not read unnecessary contact history to predict a downstream decision that cannot be established. Existing trigger-origin and historical role/delivery state cannot be reconstructed completely. Experiment reuses `assignVariant` only for hypothetical unsaved assignments; saved assignments always retain their original variant and remain in the bounded assigned cohort even if current eligibility changed. Mature observable outcomes can use `analyzeBinary`/`analyzeTimeBlocks` descriptively; unchecked historical guardrails withhold statistical support, confidence intervals and probability claims. No `ExperimentService.assign/result`, `InterventionService.propose`, activation projector, queue or mutator is invoked.

The response includes evaluation time, settings revision and an input fingerprint, plus matched/not-matched/unknown aggregate counts and explicit limitations. Optional `asOf` + `sourceHash` query parameters request replay from the same still-available saved input. They are strict ISO time/hash metadata only, bounded to current detailed retention and never in the future; no user-provided events, fixture values, code or episode selectors are accepted. Changed/removed saved input returns `PREVIEW_SAVED_SOURCE_CHANGED`; the old input is not silently regenerated or retained. Identical fingerprints use deterministic existing engines; this is not permanent historical replay after source deletion or a population/causal forecast. Disabled live features are explicitly marked simulation-only; out-of-plan or missing ANALYZE sources remain unavailable.

Japanese/English UI adds the aggregate result, unknown/empty/truncated/disabled explanations and an explicit same-input replay button while retaining cancel/back/in-flight suppression. The existing BFF mock assertion is updated for the replay/authority arguments, and the existing legacy-response UI case follows the changed tab/fallback labels; no new test suite or validation run was started. All earlier and added execution/type/lint/build/browser/DB checks remain NOT RUN pending the parent's permitted sequence.
