## 0. 結論と検証状態

条件分岐、演算、文字列、Run内変数、一覧、自作ブロックを、Scratchの表示opcodeを全体棚卸しし、制御・演算・変数・リスト・自作ブロックを一つずつ照合して補う。演算の数学関数は14選択すべてを対象とする。特に「それ以外でもし（elif）」を直接編集できるUI、Scratchの数学関数全14選択、負数・空値・型・文字・一覧境界、有界条件反復、再開時に同じ処理をやり直さない契約を明確にする。

この文書はScratch互換エミュレータの仕様ではない。Scratchの学習用動的変換、無限実行、スプライト、クラウド変数等をNEXUSへそのまま移植しない。何を参照し、同じ目的をどう提供し、何を今回は提供しないかを表に残す。「全ブロックを参照」と「全機能を同じ挙動で実装」は別の範囲である。

## 1. 変えてはいけない承認済み境界

1. 単一待機もRun全体も最大7日。Run開始からの絶対期限を、Wait・子呼出し・再試行・再開で延長しない。7日は経過時間604,800秒で、地域の暦日加算ではない。
2. 再開に必要な状態はRun実行終了後7日以内に削除する。必要がなくなった状態はより早く削除できる。ログには本文も変数内容も保存しない。
3. 実行をまたぐ永続変数、任意の外部HTTP送受信は今回除外。
4. 危険な管理権限付与、BAN、kick、大量削除は今回除外。ブロックを増やしてこれらへ抜ける経路を作らない。
5. 無料招待Betaでも同じブロック言語を使う。実行量・件数・深さ・同時数等の製品上限は実機計測後の設定値。未計測の数字を固定上限として捏造しない。
6. 外部操作の結果が不明なら自動再送しない。後続の新しい外部変更も、既存の照合・停止契約を満たすまで進めない。
7. 同じRunの同じ動的な乱数評価は初回確定値を使い、再開・再試行・画面再描画で引き直さない。

無限ループ、再帰、任意コード、自由正規表現、任意JSONによる認可情報生成は追加しない。必要な目的は有界の反復、型付きの値、登録された手順で満たす。Scratch用コードのコピーやライセンス採用を承認する文書でもない。

## 3. 共通型・評価・エラー契約

### 3.1 値と効果

| 型/状態 | 意味・制約 |
|---|---|
| Number | 有限IEEE 754 binary64。NaNと±Infinityは保存も入力も不可。-0は公開値・比較・保存時に+0へ正規化 |
| Integer | Numberのうち安全整数（絶対値2^53−1以下）。回数・添字・件数に使用。小数を自動丸めしない |
| Boolean | true/falseのみ。0、空文字、Ref、Optionalから暗黙変換しない |
| ConditionResult | true/false/unknown。unknownは登録された状態読取りが確定できないこと。型エラー、未入力、外部操作結果不明とは別 |
| PlainText | Unicode文字列。入力時に不正なUTF-16サロゲート列を拒否し、黙って置換文字にしない。ユーザー指定の正規化以外では文字を変えない |
| List<T> | 同型・有限・順序付き。要素内のOptionalは宣言があるときだけ。外部から無制限に一覧を取得する能力を含まない |
| Optional<T> | 正常な省略に限るsome/none。空文字、0、false、空Listは値あり。未初期化・取得不能・権限不足をnoneにしない |
| ParseResult<T> | 明示的な文字→値変換の成功/形式不正。成功枝のみTへアクセス可 |
| FindResult<T> | 要素検索のfound(value:T,index:I)/not_found。0番目や空文字の代用値を返さない |
| IndexResult | 位置だけの検索結果found(index:I)/not_found。FindResult<I>の二重位置表現を使わない |
| OperationOutcome | サーバー由来の成功/確認済み失敗/未開始/中止/結果不明。ユーザーがRecordや文字から捏造できない |
| Ref | ChannelRef等の安定識別子＋範囲。Numberや表示名の一致へ変換しない。表示名を使うための暗黙外部読取りなし |

値式は左から右へ決定的に評価する。ただしAND/OR、条件付き値、Optionalの代替値は後述の短絡に従う。純粋式は送信、外部read/write、時計取得、新規乱数、Wait、承認、Run変数変更を含まない。明示操作が確定した値を後続の純粋式で読むことはできる。

### 3.2 エラーを値へ隠さない

型不一致、必須欄未入力、未初期化、スコープ外、定義域外、ゼロ除算、添字外、予算超過、期限切れはそれぞれ診断コードを持つ。通常の演算は「NumberまたはBoolean等の宣言値、または評価失敗」であり、失敗を0/false/noneへ変換しない。正常な代替が必要なら明示ParseResult/Optional/登録Resultを使う。

保存前と有効化前に全枝の型・構造・静的に確定する不正を検査する。実行時は選ばれた経路と評価された式の動的値だけを計算する。静的に不正なグラフを「実行しないはず」で有効にしない一方、実行時に短絡で未評価の式は計算エラーを発生させない。エラーは該当ブロック・入力名・修正方法へリンクし、secret、本文、変数内容、raw例外をログへ出さない。

### 3.3 数値入力と精度

Number欄の半角10進数・小数・指数表記の受入書式は型schemaで固定する。Integer専用欄は半角整数のみで、桁区切り・全角・指数を黙って変換しない。PlainTextからNumberへはEX11を明示し、全体一致で解析する。空文字、空白だけ、"12abc"、"NaN"、"Infinity"は変換失敗。任意のBooleanを数値化しない。

非ゼロsubnormal値は許す。この規則は通常の数値演算に適用し、明示した丸め/切下げ等、および乱数仕様に定める有限値への離散化は除く。数学的に非ゼロの結果がbinary64で0へ潰れる通常演算はNumericUnderflowとする。厳密な相殺による0は正常。数学的な非ゼロ性が判定できない近似実装で、この境界を勝手に成功0へ変えない。

Numberはbinary64の計算誤差がある。0.1+0.2の結果は0.30000000000000004で、厳密な「=0.3」はfalse。勝手なepsilon比較はしない。必要なら独自追加「ほぼ等しい」の絶対許容誤差/相対許容誤差を明示し、認可・ID・正式承認には使用不可。金額の厳密計算を保証しない。安全整数範囲を超える整数リテラル/整数目的の結果は拒否し、IDは必ずRefにする。

Number全域の範囲は型の特性であり製品性能の上限ではない。文字・件数・深さ・評価回数・CPU・中間値bytesは実機計測後に決まる共通予算の検査対象。全子・全枝・全反復の累計で消費し、Listを1変数へ詰めても回避できない。

### 4.1 数学関数14選択を省略しない

| Scratch mathop選択 | NEXUS表示 / EN | 型と定義域 | 境界・例 |
|---|---|---|---|
| abs | 絶対値 / Absolute | N→N | abs(-4)=4 |
| floor | 切り下げ / Floor | N→N | floor(-1.2)=-2。負数で0方向へ切らない |
| ceiling | 切り上げ / Ceiling | N→N | ceil(-1.2)=-1 |
| sqrt | 平方根 / Square root | N（x≥0）→N | sqrt(0)=0、負はDomainError |
| sin | サイン / Sine | 角度N（度）→N | sin(0)=0、sin(90)=1。ラジアン入力なら明示変換 |
| cos | コサイン / Cosine | 角度N（度）→N | cos(0)=1、cos(180)=-1 |
| tan | タンジェント / Tangent | 角度N（度）→N | 90+180k度はDomainError。極付近は有限性/精度に注意 |
| asin | 逆サイン / Arc sine | N（−1≤x≤1）→度N | asin(1)=90。範囲外をclampしない |

| atan | 逆タンジェント / Arc tangent | N→度N | atan(1)=45 |

| e ^ | eの[値]乗 / e to power | N→N | e^0=1。非有限結果はOverflow、0へunderflowした場合はUnderflow |
| 10 ^ | 10の[値]乗 / 10 to power | N→N | 10^2=100。overflow/underflowを明示失敗 |

三角・逆三角・対数・指数はサーバーの版固定した数値ルーチンを正本にする。ブラウザのMath結果で本番判定を確定しない。本書の精度提案は、入力binary64をその値どおりの実数とみなし、一般値の出力誤差を正しく丸めたbinary64参照値から4 ULP以内にすること。0/subnormal近傍では1 ULPを最小正subnormalとして扱う。これはNEXUSの提案受入基準であり、Scratchの保証や実測結果ではない。sin/cos/tanの角度域は全有限Number（度）とし、厳密な周期剰余に基づく引数低減を行う。sin/cosの90度の整数倍等の表に示す代表値は正確な0/±1、tanの極はDomainErrorを要求する。浮動小数の素朴な度→radian変換と巨大角度の丸めへ仕様を委ねない。採用ライブラリ/アルゴリズムはこの全域・精度・underflow契約を満たすことを実装前に検証する。満たせない場合は実装準備未完了として差分提案へ戻し、承認なく入力域を狭めない。製品上の「=」を自動epsilon比較にはしない。

### 4.2 余り・丸め・範囲の具体契約

**既存丸めとの互換性。** 旧block-editor改訂第4.2節は半値を絶対値の大きい側へ丸める提案（-1.5→-2）だった。本書初稿の半値+∞への統一は、その旧意味と一致しない。最新7承認には丸め方式変更の承認は含まれない。したがって既存の保存定義・実行中Run・opcodeの意味は変更しない。現行Windows実装の方式は未実査であり、旧提案どおりに実装されているとも断定しない。

追加案は明示モード `tiesAwayFromZero`（半値は0から遠い方）と `tiesTowardPositiveInfinity`（半値は大きい方、Scratch方式）をUI文言・schemaに保持する。既存定義は元のschema/runtime版に従い、modeがない旧定義へ推測で新modeを補わない。新規作成で方式が未指定なら選択を求める。利用者が既存下書きのmodeを明示変更したら意味変更として新revision・再検証・再試運転・影響再確認を要求し、実行中Runへ遡及しない。モード値の実際の保存形式は現行schema照合後に決め、旧文書だけから実装を変えない。

この節の以下の半値+∞の例と受入試験T014/T015/T121/T127は、明示的に追加Scratch方式を選んだ場合の案である。既存のroundすべてに適用する置換命令ではない。小数桁丸めでも同じmodeを明示し、既存modeを維持する。いずれも追加実装前の承認対象。


- modは数学的にA−B×floor(A/B)。-7 mod 3=2、7 mod -3=-2、-6 mod 3=0。実装は中間overflowを起こす素朴な式に限定せず、有限結果と除数符号を検証する。B=0はエラー。Scratchの数値丸め誤差まで互換保証しない。
- 追加Scratch方式の整数roundは最寄り整数、ちょうど半分は+∞方向。1.5→2、-1.5→-1、-0.5→0。Math.roundと同じ意味を採るが、負の0は保存しない。
- 独自追加「小数[桁数]桁に丸める / Round decimal places」は、桁数Iと丸め規則を表示。半値の規則は明示選択し、ここでは追加Scratch方式（半値+∞）を説明する。現在のNumberの最短往復10進表現を10進有理数として丸め、その後Numberへ戻す。したがってリテラル1.005を2桁へ丸めると1.01。素朴なx×100→roundの誤差に仕様を委ねない。本書の公開域提案は-308～308の整数。負の桁は10、100等の位へ丸める（round decimal(1234,-2)=1200）。域外はPrecisionRangeErrorで、近い値へ変更しない。この範囲は未計測の利用量枠ではなく言語APIの提案。中間計算は10進有理数で行い、最後に最寄りbinary64へ戻す（同距離ならties-to-even）。10進半値を+∞へ丸める第1段階と、このbinary64再表現の丸めを区別する。最終値が非有限ならOverflow。明示roundによる0は正常とする。アルゴリズム版をschemaに固定する。
- 「切り捨て / Truncate toward zero」はScratchのfloorとは別の独自操作。-1.8→-1。floor(-1.8)=-2と並べてヘルプへ表示。
- 独自追加のmin/max、clamp、<=、>=、!=は既存EX01/EX02の具体形。clamp(x,lo,hi)はlo≤hi必須。順序逆転を自動交換しない。範囲判定は両端の包含を明示するが、既存の時点範囲は開始以上・終了未満、終日日付範囲は両日包含という契約を変えない。
- 有限番号一覧range(start,end,step)はI×I×I→List<I>。終端包含を表示し、step=0・方向不一致・件数予算超過・生成中の安全整数外を拒否。start=endはstepの符号にかかわらず1要素。空の範囲が必要なときは明示空一覧を使う。

### 4.3 乱数は全表示機能を対象にしつつ再開安全に変更

Scratchのpick randomは上下逆転を交換する。整数/小数の分岐は元入力のCast.isInt判定に依存し、number入力なら整数性、string入力なら小数点「.」の有無で決まる。表記によって挙動が変わり、例えば文字列の指数表記では数値化後の上限を超える例もある（別冊第7.3節）。数値だけを見れば常に整数端/小数端で正しく分かれるという互換仕様にはしない。NEXUSでは同じカード内に「整数 / Integer」と「小数 / Decimal」の明示モードを置く。入力例の数字で自動的に意味を変えない。

| モード | 入力と出力 | 契約 |
|---|---|---|
| 整数 | Iのlo/hi→確定I | lo≤hi。両端含む。lo=hiはその値。各整数を等確率にする方式。範囲幅計算で安全整数overflowを起こさない内部整数演算を使用 |
| 小数 | 有限Nのlo/hi→確定N | lo<hiならlo以上hi未満、lo=hiならその値。逆転拒否。数学的連続実数の一様性とは説明せず、版固定した有限精度方式と出力解像度を明記 |
| 重複なし抽出/シャッフル（NEXUS独自） | 固定List<T>、件数I→確定List<T> | 件数0は空。候補超過/負数/小数拒否。空shuffleは空。キーと重複方針を先に固定 |

小数方式は一様な53bit整数kをu=k/2^53へ写し、有限で安定した補間でlo+u(hi-lo)に相当する値を作る。中間overflowを避け、丸めがhiへ到達した場合はhi未満の隣接表現可能値を使う。最終範囲を再検査する。非常に狭い範囲は同じ値になり得る。金銭抽選、認証秘密、暗号学的安全性、公正性証明には使わない。

固定キーはRunID、FlowRevision、BlockInstanceID、子呼出しpath/動的呼出し回、並列枝path、全囲みループの反復番号。初回の入力snapshot/モード/出力を一意・原子的に確定してから後続へ進む。同じキーの再試行は現在変数で入力を再評価せず確定値を読む。別反復は別の生成だが偶然同じ値でもよい。保存応答が消えたら同じキーの確定記録を照合し、再生成で代用しない。

乱数の結果・最小snapshotは再開状態であってログではない。保持は第1章の範囲に限定し、元データの用途/閲覧範囲を継承。本文・参加履歴の新たな保存や全メンバー収集を正当化しない。

## 5. 条件・elif・短絡評価

### 5.1 if / elif / elseの利用者向け形

「もし [条件A] なら」「それ以外でもし [条件B] なら」「それ以外」「判定できないとき」を一つの連鎖として見せる。elifは0個以上、elseは最大1個で末尾固定。不明経路は連鎖全体に1つの共通経路を基本とする。各条件がBooleanだけなら不明経路は不要。

1. 連鎖開始時の読取り可能値環境を固定する。外部状態は事前の明示readで取得し、条件式の中へAPI読取りを入れない。
2. Aから順に評価し、falseだけ次の条件へ進む。最初のtrueでその枝だけを選択し、後続の条件を評価しない。すべてfalseならelse、elseなしの文分岐は何もせず後続へ進む。
3. unknownならその時点で不明経路へ進み、後続elif/elseを評価・実行しない。不明経路未設定のC分岐は有効化不可。評価エラーはunknownでなく評価失敗で停止する。
4. 選択した枝内でエラー/拒否/結果不明が起きても次のelifへフォールバックしない。外部変更を違う枝で重ねて試さない。
5. 入れ子は独立した連鎖。内側のelseは内側だけに所属し、所属枠とインデントを表示する。
6. 値を返す分岐は全経路で同型Tを返す。Bならelse必須、Cならelseとunknown両方必須。Optional<T>を返す設計ならnoneを明示できる。未返却を0/空文字にしない。

文分岐の枝内で宣言した値はその枝だけで有効。後続で使う値は分岐の宣言出力として全正常経路から返すか、分岐前に初期化済みの同一実行フレーム変数へ明示代入する。並列枝や子手順が親変数を共有書込みすることは許可しない。

### 5.2 保存構造を壊さないelif UI

初期実装は既存CT01のfalse側にCT01を入れる構造へ正規化し、canonical graphの新しい実行命令を必要にしない。新規連鎖の各unknown辺は共通不明枝へ接続する。既存の深いif/elseに異なる不明ハンドラや追加処理が混ざる場合は、無条件に平坦化せず入れ子表示を維持する。

- 「それ以外でもしを追加 / Add else if」はelse直前へ条件・本文の組を挿入。条件だけを移して本文との対応を壊さない。
- 並べ替えは枝全体を移動。「先に一致した条件が使われます」を表示し、意味が変わるRevision差分として扱う。
- 枝の削除は中身の処遇を確認し、Undo対象。保存する中身を隠れた別経路に残さない。
- 正規化してもBlockInstanceID/branch IDを安定保持し、デバッグ位置と再開位置を単なる表示行番号で識別しない。
- 保存→読込→別表示→保存で順序、unknown辺、選択意味が変わらないround-tripテストを必須にする。

### 5.3 3値の真理値と評価順

以下はNEXUSの決定であり、ScratchのVMがAND/ORのreporter入力を先行評価する挙動とは異なる。

| A | B | A AND B | A OR B |
|---|---|---|---|
| true | true | true | true |
| true | false | false | true |
| true | unknown | unknown | true |
| false | true | false | true |
| false | false | false | false |
| false | unknown | false | unknown |
| unknown | true | unknown | true |
| unknown | false | false | unknown |
| unknown | unknown | unknown | unknown |

NOT(true)=false、NOT(false)=true、NOT(unknown)=unknown。ANDは左がfalseなら右を評価しない。ORは左がtrueなら右を評価しない。左がunknownのときは右を評価し、ANDのfalse、ORのtrueで結果を確定できる。右が評価エラーならunknownへ隠さず失敗になる。Boolean版は通常2値の同じ短絡規則。

「unknown AND falseがfalse」は論理の結論であり、権限不明を安全とみなす規則ではない。操作時の必須認可・正式承認・存在/所属検証は条件式から独立し、短絡で省略できない。any/all/findも入力順に同じ短絡で評価し、any(empty)=false、all(empty)=true。最低1件が必要な用途は件数条件も指定する。

### 5.4 分岐選択とWait再開

枝を選択したら選択IDと必要最小値、固定Revision、実行位置をチェックポイントへ原子的に記録してから枝本文を進める。Waitの後に同じifを判定し直して別枝へ移動しない。判定前に落ちた場合は同じ固定入力で評価し、純粋式なので結果は同じ。判定後の変数変更は次の別分岐には影響するが選択済み枝を遡及変更しない。ログは枝ID/状態/時刻だけで、条件の生値や本文を保存しない。

### 6.1 本体付き有界条件反復

UIは「条件が成立するまで / Until」「条件が成立している間 / While」「最大[回数]回」「期限[時点]」と本文枠を表示。最大回数は非負I必須、期限はRun期限以内で必須。無指定の無限版は存在しない。各局所期限は本文実行中にも有効で、有効期限をRun・全囲みloop・呼出し元から継承した期限の最小値とする。Wait/イベント待機/承認/子手順はこの期限を延長できず、wakeAtがこれを超える配置や動的値は拒否する。期限時には未開始の処理を止め、開始済み外部操作は証拠照合だけを許し、成功/失敗不明なら結果不明を保つ。CT03の新しいモードとして同じ反復基盤へ正規化し、CT11の読取専用Pollとは区別する。

実行手順：反復入口で期限/停止/予算を検査→条件を評価→untilならtrue、whileならfalseで正常終了→unknownなら不明経路で反復終了→継続すべきだが完了反復数が最大回数なら上限到達経路→本文実行→反復数を確定して入口へ戻る。最大N回の本文に対し条件は最大N+1回評価する。最大0でも条件は1回評価するが本文は実行しない。

終了理由はcondition_met、count_completed、broken、limit_reached、deadline_reached、unknown、cancelled、failed、external_result_unknownを区別し、上限/期限を成功へ偽装しない。条件falseが続くuntilはlimit_reachedへ進み、同じ処理を新Runとして勝手に継続しない。

本文は通常の型付き文を組める。Run内の明示代入、固定子手順、Wait、承認、許可済み外部操作も既存の制約内で使えるが、外部書込みの確定が次反復への条件。結果不明なら反復も後続外部変更も停止する。読みたい状態が外部由来なら本文の明示読取で値を更新する。短いpoll間隔による無制限API読取を許さず共通予算・許可された間隔制約を適用する。

count/for-eachの回数・一覧は入口で固定し、反復中の元一覧変更で対象を追加しない。while/until条件は各入口時点の同一フレームの現状態を読む。外部/兄弟枝の共有変数を監視する隠れたポーリングにはしない。

### 6.2 break / continue / Return / Stop

- breakは最も内側のループをbrokenで終了し、その後続へ進む。continueは当該反復の残りを飛ばし、反復消費を確定して次の入口へ。最後なら条件再判定/終了規則に従う。
- 別の子手順、別並列枝、親Run、未完了承認や結果不明を飛び越えない。Waitがpendingの間は実行位置がその場で停止しており、後ろのbreakが先に実行されることはない。
- 手順Returnは宣言出力を満たしてその呼出しだけ終了。純粋値関数は全正常経路で値を返す。ReturnをRun終了と表示しない。
- End branchはその構造化並列枝だけを終了。Joinで正常出力が必要なら出力を満たすかCancelled等の状態として扱う。
- End runは新規処理の開始を止める要求。既に始めた外部操作を取り消せたと仮定しない。成功/失敗の証跡は維持し、不明だけを不明のまま表示する。

## 7. 待機・Run終了・再開状態の保存

Run開始時にstartedAt、deadline=startedAt+7日を確定する。WaitのwakeAtはWait開始時に確定し、単一待機7日以内かつwakeAt≤effectiveDeadline（Run期限と全局所期限の最小）を満たすこと。期限と同時のwakeは期限到達の処理を優先し、新しい外部操作を開始しない。実行開始時点のちょうど7日Waitは保存できても後続本体が期限内に動けないので、UIにその意味を示す。

Run状態遷移は、変数/List代入、枝選択、反復完了、continue、子復帰、確定乱数、PC、残予算、単調な状態版を一つの論理commitとして確定する。永続checkpointを使う境界では同じトランザクション/等価な一意確定方式で保存し、「新変数＋旧PC」の混合snapshotを復元しない。遷移IDと旧状態版を照合し、同じ遷移のworker再試行を二重適用しない。純粋計算をcheckpointから再計算する場合も外部操作前の一貫した状態境界を保つ。これが必要なのは乱数やifだけでなく、通常の変数加算、一覧代入、continueを含む全Run状態更新である。外部APIのexactly-onceを保証する規則ではなく、外部結果不明は別契約のまま。

再開に必要なのは固定Revision/子版、入力の必要最小値、PC、選択済み枝ID、ループ対象/反復位置、呼出しフレーム、確定乱数、Wait/イベント相関、残予算、外部操作の一意キー/結果証跡等。本文を含む一時値は無条件にcheckpointへ保存しない。保持可能でない値が待機をまたいで必要になる場合は、その構造を有効化前に拒否し、許可された参照から明示再取得する等の別設計が必要。

Run状態は再開目的のアクセス制御された最小データ。ログ/分析/障害監視/デバッグ履歴へ変数内容をコピーしない。Run終了はcompleted、failed、cancelled、deadline_expired、unresolved_external_result等をterminalAtで確定する。結果不明がある場合もRun期限を延ばさず、未解決フラグを持つ終了状態として止め、未知を成功/失敗へ変換しない。terminalAtは初回終了確定後に動かさず、遅延成功や照合証拠が届いても削除期限を延長しない。終了後は許可された証拠補足だけで通常実行を再開しない。再開データはterminalAtから7日以内に削除し、削除後のcallbackや古いworkerから同じRunの再開状態を再作成しない。結果不明の24時間等の新しい早期自動終了時間は本書で追加しない。別の監査メタデータ保持の新設は本書で承認しない。

削除・失効・権限変更・Run中止は再開時にも操作直前にも検査する。旧Revisionの固定は古い権限の固定ではない。期限超過や再開不能を理由に新Runを自動作成し、同じ外部変更をやり直すことは禁止。

## 8. 文字列ブロックの具体契約

ScratchはJavaScript文字列のUTF-16 code unitに基づくletter/lengthや小文字化を使う箇所がある。NEXUSの利用者向け文字位置/長さは、版固定したUnicodeの拡張書記素クラスタ（EGC）を使い、絵文字や結合文字を途中で壊さない。外部APIのUTF-16数・bytes・制約は別のメッセージ検証器で計算し、見た目の1文字とAPI上の1を同一視しない。

| 操作 | 入出力 | 空・境界・同値 |
|---|---|---|
| つなぐ / Join | T×T→T、またはList<T>×区切りT→T | 空を含めて通常結合。空一覧→空文字。Number/Refの暗黙文字化なし |
| 何文字目 / Letter at | T×I→T | 1≤位置≤EGC数。0/負/小数/範囲外/空文字に位置1はエラー。Optional版が必要なら別明示操作 |
| 文字数 / Length | T→I | 空→0。例えば「A😀é」は3 EGC。元の結合形式は変えない |
| 含む / Contains | T×T→B | 既定は大小区別・正規化なしの文字列一致。空検索はtrue。検索一致がEGC途中にあっても文字列の包含は成立し得るため、位置を返すfindは境界規則を別表示 |
| 切出す / Slice | T×開始I×件数I→T | 開始1～len+1、件数≥0、開始−1+件数≤len。len+1では0件だけ許可。空で開始1/件数0→空 |
| 置換 / Replace | T×検索T×置換T×first/all→T | 空検索拒否。重なりなしで左から置換。出力サイズ/置換回数を検査。regexやテンプレート実行なし |
| 分割 / Split | T×区切りT×空項目保持方針→List<T> | 空区切り拒否。空入力＋保持なら[空文字]、除外なら[]。連続区切りの空項目を明示 |
| 大小文字・正規化 / Transform text | T×登録mode→T | case fold/upper/lower/trim/NFC等は明示選択、Unicode版固定。Ref/認可/認証値の同一性には使わない |
| 位置を探す / Find text | T×検索T→IndexResult | EGC境界から始まり境界で終わる一致を対象。先頭1始まり。未一致はnot_found。空検索は位置1を返すとヘルプに明記 |

等値比較は既定で正確な文字列一致。"A"と"a"は異なり、"é"と"e◌́"は既定では異なる。明示NFC後なら一致し得る。大文字小文字を無視する検索は別モードにし、Scratchの比較規則を暗黙に持ち込まない。表示名の一致を同一ユーザー/チャンネルと見なさない。

全文長すぎを自動切捨てして送信しない。利用者が明示切出しした場合も出所・用途・公開範囲を保つ。メンション文字列を結合しただけで通知権限が得られることもない。

## 9. 変数・一覧の全対応とスコープ

### 9.1 変数

| Scratch | NEXUS | 型/効果/境界 |
|---|---|---|
| 変数を作る（編集UI） | DA01「変数を宣言 / Declare variable」 | 安定VariableID、名前、型、初期値、説明、所有フレーム。編集操作とruntime文を区別 |
| data_variable / 変数値 | DA03「[変数]の値 / Read variable」 | 宣言T→T。初期化済みだけ参照。名前変更でIDを変えない |
| data_setvariableto | DA02「[変数]を[値]にする / Set variable」 | 同型T、Run状態の明示代入。値評価が失敗すれば元値を維持 |
| data_changevariableby | DA02具体形「[変数]を[差分]ずつ変える / Change variable」 | 書込み可能N変数×N。read/add/validate/writeを同一フレームで原子的に確定。未初期化を0にしない |
| data_showvariable | 「値を確認 / Inspect value」のUI | 処理ブロックによる外部公開ではない。権限者がその場で確認、記録/本文ログ化なし |
| data_hidevariable | 「値の表示を閉じる / Hide inspector」のUI | 表示を閉じても変数は変更/削除しない。非表示を秘密保護の根拠にしない |
| 全スプライト用/このスプライト用 | Runフレーム/子手順ローカル/反復・枝の字句スコープ | スプライトや複数Run共有へ直訳しない |
| クラウド変数 | 今回対象外 | 実行をまたぐ永続変数を新設しない |

同じ実行フレーム内の逐次if/loop本文は、見えている書込み許可Run変数へ明示代入できる。各枝/反復で宣言したローカルは外へ漏れない。子手順は値渡し引数とローカルを持ち、親変数へ暗黙書込みしない。並列枝は入力snapshotを受け、親/兄弟と共有書込みしない。Join後の親は宣言済み枝出力を読んで自分の変数へ代入する。純粋関数は引数読取りのみで変数代入を含めない。

### 9.2 リスト表示ブロックを一つずつ対応

全変更操作は新List<T>を返す純粋値操作。既存の変数を更新するにはDA02を明示する。「一覧変数へ追加」の初心者向け文形を用意しても、内部意味は読み取り→純粋変更→同じ変数へ代入で、効果表示を隠さない。

| Scratch opcode/表示 | NEXUSの具体形 | 型と境界 |
|---|---|---|
| リストを作る（編集UI） | 「一覧を作る / Create list」 | 型Tを宣言。空一覧にもTが必要 |
| data_listcontents / リスト値 | 「[一覧]の値 / Read list」 | List<T>そのものを返す。Scratchの暗黙空白結合文字列にはしない。表示は明示join/format |
| data_addtolist | 「[一覧]の末尾へ[値]を追加 / Append」 | List<T>×T→List<T>。順序/重複維持、容量検査 |
| data_deleteoflist | 「[一覧]の[位置]を削除 / Delete item」 | 1..lenのI、空/範囲外拒否。新Listを返す |
| data_deletealloflist | 「[一覧]を空にする / Clear list value」 | 同型空List<T>。元変数は別代入まで変わらない |
| data_insertatlist | 「[位置]に[値]を挿入 / Insert item」 | Iは1..len+1。空一覧の位置1を許可。順序維持 |
| data_replaceitemoflist | 「[位置]を[値]に置換 / Replace item」 | 1..len、同型T。範囲外/小数拒否 |
| data_itemoflist | 「[一覧]の[位置]番目 / Item at」 | List<T>×I→T。1..len必須。空や不正位置を空文字にしない |
| data_itemnumoflist | 「[値]が最初にある位置 / Find first index」 | List<T>×T→IndexResult。見つからなければnot_found。0番目を返さない |
| data_lengthoflist | 「[一覧]の件数 / List length」 | List<T>→I。空は0 |
| data_listcontainsitem | 「[一覧]に[値]がある / List contains」 | 同型、登録等値キー→B。空はfalse |
| data_showlist | 「一覧を確認 / Inspect list」 | 認可された一時デバッグUI。外部投稿/永続監視ログではない |
| data_hidelist | 「一覧表示を閉じる / Hide list inspector」 | 表示だけ変更。内容や保持期限を変えない |

Scratchのlast/random/any/all等の特殊添字・文字による指定はNEXUSのNumber欄へ入れない。「最後の項目」は明示の専用形（空ならOptional noneまたは厳密取得エラーを形で分離）、「無作為の位置」はEX12で一度確定してから使う。「すべて削除」はClearの別形。小数添字のfloorや不正位置の無視は採用しない。

等値はNumberの厳密比較、PlainTextの第8章規則、Refの安定IDと所属範囲、Recordなら登録キーを使う。異型比較は拒否。findは入力順の最初の一致。重複除去は最初を残す安定方式。sortは同順位で入力順を維持し、表示名の取得を裏で行わない。

既存のmap/filter、sum/average/min/max、group、zip、chunk、集合演算は維持。空sum=0、空average/min/max=Optional none、空any=false、空all=true。zip長さ不一致はエラー、chunk件数は正I。List/Record/文字へ加工しても元データの目的/公開境界/保持を引き継ぐ。

## 10. 自作ブロックの全対応

| Scratch要素 | NEXUSの対応 | 契約 |
|---|---|---|
| ブロックを作る（編集UI） | 「共通手順を作る」「自作の値ブロックを作る」 | 作成と実行呼出しは別。名前/引数/出力/効果を宣言 |
| procedures_definition | CT08/09の共通手順定義 | 固定Revision、型付き引数、名前付き戻り値。文の副作用は明示 |
| procedures_call | 「[手順]を呼ぶ / Call procedure」 | 引数を左から評価→値渡し→呼出し結果。子予算/期限/権限は親から継承 |
| argument_reporter_string_number | 型付きNumber/Text等の引数参照 | Scratchの兼用動的型にせず宣言型T。欠落した引数は有効化エラー |
| argument_reporter_boolean | Boolean引数参照 | B。Cが必要なら別明示型。空の条件ソケットをfalseにしない |
| 画面を再描画せずに実行（warp） | 実装性能設定の参考のみ | 安全検査・Wait・キャンセル・予算を無効にする利用者モードは作らない |
| 再帰呼出し | 今回除外 | 依存グラフの直接/間接循環を有効化前に拒否 |
| 戻り値付き値ブロック | CT15（NEXUS独自） | 純粋な引数→T。Bなら条件形。全正常経路で同じT、外部read/write/時計/乱数/Wait/代入不可 |

引数/出力は安定IDを持つ。名前変更は参照を壊さない。必須引数追加、型変更、必須出力削除は新しい非互換Revisionとして未対応呼出しを診断し、自動で0/空を補わない。呼出しの更新は下書きの明示操作で、開始済みRunは旧版/旧子版に固定。定義上限、呼出深さ、全評価量は共通予算。

例：「必要数 / Required count」は人数Nと予備Nを受け、人数+予備を返す。80と20なら100。二つの引数以外の隠れた100や最新人数を読み取らない。出力を回数に差し込むときは安全な非負整数という受け側検査を別途行う。

## 11. 差込みUI・検索・試運転

各欄はLiteral、VariableRef、Expression、PureFunctionCallのうち保存する1方式を明示する。説明用の「例:10」はplaceholderで、未入力を10として実行しない。設定済み初期値、試運転専用値、本番起点値は視覚/読み上げともに区別する。

- Number欄は丸い値形、Booleanは条件形、ConditionResultは「不明を含む」表示、処理は積み重ね、制御は本文枠。色だけで識別しない。
- 「固定値を入力 / Enter value」「変数を使う / Use variable」「計算を入れる / Insert expression」「自作の値 / Custom value」を同じ欄から選べる。型/スコープ/出所が合う候補だけを有効にする。
- 「if」「もし」「elif」「それ以外でもし」「mod」「余り」「sqrt」「平方根」等の日英同義語で具体形を直接探せる。巨大な「演算」1項目だけで隠さない。
- 不適合差込みは拒否理由と期待型を表示。IDを数値化、文字を勝手に数値化、falseを未設定扱いする自動変換はしない。
- 変数未確定のプレビューは「実行時に決まります」。試運転値は「この試運転だけ」と表示し、本番Literalへ保存しない。
- Tabで入力間移動、Enterで候補確定、Escapeで変更前へ、キーボードで枝追加/上下移動が可能。スマホは同じ構造の手順一覧を正本と同期する。
- エラーはブロックID/入力名へ戻れる。値の実内容をログに残さず、必要な入力内容は権限を持つ利用者の現在画面だけで扱う。
- 試運転は外部送信しない。分岐経路、未評価式、loop終了理由、選択済み乱数、残予算、最大Run期限を確認する。再表示で乱数を作り直さない。
