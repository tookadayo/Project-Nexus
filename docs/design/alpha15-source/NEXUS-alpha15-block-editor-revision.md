# NEXUS alpha15：Webブロック編集への改訂差分

2026年10月14日。設計案。実装・コード照合・実機試験は未実施。

## 0. この文書の使い方

alpha15の自動化を、Scratchのように**文を上下につなぎ、条件や繰り返しの中へ入れるWeb編集画面**に改訂する。一般的な箱を線で結ぶ編集画面は、新しい標準画面として残さない。alpha15で自動化全体を完成させ、alpha16でルールベースAIを詳しく設計する区分は維持する。

本書は「NEXUS alpha15 設計図」と第4版統合設計のうち、編集・式・変数・変換・関連試験を置き換える差分である。これ以外の実行、認可、送信、結果不明、中止、削除、保持、外部接続の契約は引き継ぐ。旧説明と競合する場合、この改訂の対応箇所を優先する。元の設計書を黙って書き換えるものではない。

通常ChatGPTの同じ設計チャットで、①組み立て体験、②保存・実行との接続、③技術候補と契約の整合を検討し、第三回の補完で矛盾を修正した。その回答をそのまま転載せず、本書では対応表・検証条件を整理した。製品の完成、試験合格、企業品質を証明する文書ではない。

## 1. 利用者ができること

条件分岐、変数、数値・文字・日時の計算、回数や対象一覧を決めた繰り返し、期限付き待機、並列処理、引数と結果を持つ共通手順を組み合わせられる。簡単なプログラミングに相当する範囲を含むが、何でも実行できる仕組みにはしない。

- 開始条件・使える情報・操作は登録済みのものから選ぶ。
- 自由なJavaScript、Python、SQL、任意URLへの通信、無制限の繰り返し・再帰は提供しない。
- 元投稿本文を使う条件、自由記述・添付などの未採用機能を、文字ブロックで使えるように見せない。将来の一時処理は必要な規約・権限・安全条件の別検討とする。
- 個別待機7日以内の了承を維持する。実行全体の期限、新設データの保存期間、外部接続A/Bの採用は従来どおり未承認である。
- ブロックの接続だけで本番の変更を開始しない。保存、送信なしの試運転、影響確認、有効化を経て、設定した開始条件で動く。

## 2. 入口と画面

### 2.1 一つの編集構造

「受付の案内」「ボタンで案内」「予定のお知らせ」「管理者からのお知らせ」の初期テンプレートは、同じブロック定義の未有効な下書きを作る入口である。作れるものを4例に限定しない。

1. 例または空の下書きを選ぶ。
2. 開始ブロックの下へ処理を追加する。
3. 条件・繰り返しなどの内側へ処理を入れる。
4. 入力欄から固定値や使える情報を選ぶ。
5. 送信せずに試し、判定理由と予定される変更を確認する。
6. 対象・内容・件数・権限・保存する情報を確認して有効にする。

PCの主画面は左に種類別の部品と検索、中央にブロック、右に選択中の設定と例を置く。下部または一覧に入力不足をまとめる。上部には対象サーバー、名前、保存状態、有効版との違いを常時示す。

「手順一覧」は同じ親・枝・順番・入力を階層リストで編集する補助表示である。別の意味モデルを持たず、主画面と安定したIDを共有する。狭画面・キーボード・読み上げではこの表示からすべての操作を完了できるようにする。表現できないものを削除・平坦化して切り替えない。

### 2.2 接続の案内

- ドラッグ中は入る位置・内側の範囲を形と文字で示す。置く前に、動くブロックが1個か後続一式かを確認できる。
- 合う場所だけ接続候補にする。型・権限・利用時点が合わない場所には理由を出す。
- 「ここに追加」「前に追加」「後ろに追加」「中へ移動」「外へ移動」「上へ」「下へ」をメニューから操作できる。
- 移動で値の利用範囲が変わる場合は再検証する。位置を変えただけだとして認可・依存検証を省略しない。
- 詳細設定は必要時に開く。期限・承認要否・対象・最大件数・利用不可理由は隠さない。
- 折り畳みは表示だけ。中に未入力や有効化を妨げる項目があれば、折り畳んだ見出しにも件数と理由を表示する。

## 3. 色・形・名前

色は種類を探す補助、形は文・条件・値を区別する補助とする。色だけ、形だけで意味やエラーを伝えない。以下の色は配色案で、実測したコントラスト値ではない。

| 種類 | 配色案 | 画面名 JA / EN | 形と例 |
|---|---|---|---|
| 開始 | 金色 | きっかけ / Start | 上へつながらない開始形。「時間になったら」 |
| 条件と繰り返し | 橙 | 条件・繰り返し / Conditions &amp; loops | 処理を包むC字形。「もし…なら」「3回繰り返す」 |
| 時間・承認 | 黄土 | 待つ・承認 / Wait &amp; approval | 文の形。結果経路と期限は展開して確認 |
| 値と計算 | 緑 | 値・計算 / Values &amp; calculations | 数値・文字・日時・参照は値の形＋型名。真偽条件は六角形 |
| Discord操作 | 青 | Discordの操作 / Discord actions | 文の形。「案内を送る」「ロールを付ける」 |
| NEXUS内の情報 | 青緑 | 受付・集計 / Requests &amp; counts | 状態の読取りと変更の名前を区別 |
| 再利用 | 紫 | 共通手順 / Shared steps | 文の形。呼出先、引数、固定版、結果名を表示 |
| 外部接続 | 灰青 | 外部サービス / External services | 未採用時は利用不可理由を表示。勝手に有効化しない |

「もし」は六角形そのものではなく、六角形の条件入力を受けるC字形の文である。通常の「もし／それ以外」に加え、情報を確認できない経路を明示できる。既定では変更せず理由を示す。並列は名前付きの複数領域を包み、開始した各枝の結果がそろうことを示す。上限3枝は提案値である。

終端形は「この実行を終える / End this run」。共通手順内の「結果を返す / Return result」と区別する。枝や繰り返しの下端はそれだけで実行全体の終了を意味しない。

## 4. 値・変数・計算

### 4.1 「情報を選ぶ」

入力欄には型に合う候補を出す。各候補に平易な名前、種類、出所、使える時点、架空の例を表示する。例は実際の取得成功を意味しない。

- 固定値：通知先、回数、時間、管理者が作る案内文。
- この実行の情報：開始日時、許可されたイベントID、申請者など、その起点で実際に得られるもの。
- 前の処理の結果：読み取った受付状態、計算結果、共通手順の戻り値。
- 現在の繰り返しの情報：対象、回数。制御用の値は書き換え不可。

名前を変更しても参照は安定したIDで保持する。名前が同じでも別サーバー・別の枝・別の呼出しの値を混ぜない。権限外のチャンネル・ロール、他サーバー、秘密の中身は候補へ出さない。画面の候補制限に加え、サーバーでも同じ条件を検証する。

### 4.2 型と純粋な演算

| 型・処理 | alpha15の設計範囲 | 拒否・注意 |
|---|---|---|
| 数値 | 加減乗除、大小・一致比較、四捨五入・切上げ・切下げ | 有限値のみ。0除算、範囲外、整数欄への小数はエラー |
| 文字 | 固定文字の結合、長さ、許可した書式での数値・日時の表示 | 元投稿本文・秘密を取得する機能ではない。自由な式文字列・正規表現コードは受け付けない |
| 日時 | 時点の比較、時点＋期間、曜日を確認 | 日時と期間を別型にする。暗黙の文字→日時変換はしない |
| 条件 | 等しい・異なる・以上・以下・範囲内、かつ／または／ではない | 情報不足を不成立に変えない。認可検査を条件式で免除しない |
| 選択値 | フォーム等の登録された選択肢 | 表示名でなく定義内の値で照合。知らない値は拒否 |
| 参照 | 許可されたChannelRef、RoleRef、MemberRef、TicketRef等 | 数値IDと無条件に交換しない。所属・現在の権限も検証 |
| 一覧 | 同じ型の有限要素一覧 | 件数上限と要素型を検証。任意の巨大データを格納しない |

式は許可した演算子の構文木で保存する。生成JavaScriptやevalを実行経路に使わない。純粋な式の中でネットワーク読取り・送信・ロール変更・待機を発生させない。現在状態の取得は独立した読取りブロックとして見せる。

数値は有限の倍精度数を基本とする案で、金額の厳密計算には使わない。四捨五入の中間値は絶対値を大きくする側、切下げ・切上げはそれぞれ数学的floor/ceilとする提案。丸め桁数にも制限を設ける。文字の表示上の長さと、保存・送信先のバイト数や文字数制限は別に検証する。いずれも採用する実装で境界値試験が必要である。

日時はUTCの時点、期間は時間量として扱い、曜日の判定・表示は明示したタイムゾーンを使う。「24時間後」と「次の日の同じ現地時刻」を同一扱いしない。後者や定期実行は既存の夏時間規則を使う。再試行のたびに「今」を勝手に読み直す純粋式は作らず、使用する時刻の出所を固定する。

### 4.3 範囲と代入

| 範囲 | 読み書き |
|---|---|
| 設定・起点入力 | 型付き、読取り専用 |
| 直列の実行変数 | 明示的に作成・代入。未代入のまま利用不可 |
| 条件内の値 | 内側だけ。外へ出すなら全正常経路で型と値を満たす明示的な結果が必要 |
| 繰り返し | 対象と回数は読取り専用。各反復の一時値と、意図して更新する直列変数を区別 |
| 並列の枝 | 開始時の親入力を読取り専用で受け、枝内の値だけを書き換える |
| 共通手順 | 引数は読取り専用。呼出しごとに独立した一時値と名前付き戻り値 |

並列枝から親・兄弟へ直接代入しない。合流後は「枝Aの件数」「枝Bの結果」を明示的に選ぶ。終了が早い枝の値で上書きする方式は採らない。分岐内だけで作った値、失敗した手順の未確定結果を空文字や0で補完しない。ループを0回実行しても、未作成の結果を後続で使えない。

## 5. 条件・繰り返し・待機・共通手順

### 5.1 不明・入力エラー・外部操作の結果不明

この三つを別に扱う。

1. **入力エラー**：未入力・未接続は未完成として明示し、警告付き下書き保存はできるが有効化は拒否する。宣言型に反する設定値、未知型、壊れた式、既に判明している0除算は保存自体を拒否する。未入力を任意の不正値で表現しない。妥当な式でも実行中の値によりエラーとなった場合は、外部操作前に既存の失敗規則で止める。
2. **条件を確認できない**：必要な状態を読めず、条件の答えが不明。三値条件と明示的な安全経路へ渡す。権限不足・削除等の理由を示し、必要情報がなければ変更しない。
3. **送信・変更の結果を確認できない**：外部書込みを試み、その成否を確定できない。既存の照合・新規送信停止・中止・最終結果不明の規則へ渡す。単なる条件不明とは別である。

条件は成立、不成立、不明の三値。純粋な式は左から短絡評価する。`false AND unknown=false`、`true AND unknown=unknown`、`true OR unknown=true`、`false OR unknown=unknown`、`NOT unknown=unknown`。未初期化や型不正を三値の不明へ隠さない。認可は条件式の外で毎回確認するため、「または成立」で権限不足を回避できない。

条件の正常な選択経路だけが通常の後続へ進む。承認拒否・期限切れ・中止・失敗・外部結果不明が、C字形の底へ来たという理由で通常成功に変わることはない。

### 5.2 有限繰り返し

- 「一覧の各項目について」は開始時に固定した型付き一覧を順に処理する。既定の途中失敗は残り停止。
- 「n回繰り返す」は開始時に回数を固定する。提案範囲0〜25回。0回は内側を一度も実行せず、負数・小数・非有限値・26以上は拒否する。
- 数値繰り返しには新たな登録演算 `N-VAR.count_range(Number〈整数・0〜25〉) → List&lt;Number&gt;` を設計追加し、1からnの有限一覧へ変換して `N-FOREACH(List&lt;T&gt;)` で扱う。ここで整数はNumberへの入力制約であり、正規型へ新しいInteger型を追加しない。N-LISTの既存の参照一覧取得と混同しない。count_rangeが既に実装されているとは扱わない。
- 現在の対象・回数を変更して反復数を増やせない。入れ子、並列、共通手順の合計予算を計算する。
- 「状態をもう一度確認する」はN-POLLとして回数・間隔・期限を表示する。読取り専用であり、結果不明の書込みを繰り返す用途には使わない。
- 一般的なwhile、無限ループ、再帰、循環接続は許可しない。

### 5.3 待つ・並列

| 画面表示 | 正式な処理 | 意味 |
|---|---|---|
| 時間まで待つ / Wait until | N-WAIT | 指定時点まで待つ。期限・中止・権限を再確認 |
| 操作や変更を待つ / Wait for an action or change | N-AWAIT | 対象イベントと対応するID、資格、期限を照合 |
| 承認を待つ / Wait for approval | N-APPROVE | 固定した内容に適格者が承認。拒否・期限切れを分ける |
| 同時に進める / Run in parallel | N-PARALLEL＋N-JOIN | 開始した全枝の結果をそろえる。失敗・結果不明を成功へ変えない |

待機・子呼出しで親の期限・中止・残予算を更新し直さない。共通手順も現在権限を独立確認する。画面で枝をつなぐことは、本番の同時送信数を自由に増やすことではない。外部書込みは既存の送信管理を通す。

### 5.4 自分で作る共通手順

利用者が許可済みのブロックをまとめ、名前、説明、型付き引数、名前付き戻り値を定めて保存できる。これがNEXUSの「自分で作るブロック」に当たる。

例：「運営へ案内する」は通知先ChannelRefと固定案内Textを受け、確認できた送信結果参照を返す。呼出し元では文として「共通手順を使う」を置き、正常終了後にその結果を選ぶ。送信を行う共通手順を、計算欄の丸い値ブロックとして暗黙実行しない。

- N-CALLは固定した子の版を呼ぶ。新しい子版を保存しても既存の親版は黙って変更しない。
- N-RETURNは全ての宣言済み必須出力を、全ての正常経路で返す。戻り値不要なら明示的に結果なしとする。
- 子の引数は読取り専用。親への隠れた代入や全サーバー共通の可変変数を設けない。
- 失敗・中止・外部結果不明から、空の成功値を返さない。
- 深さ3、再帰禁止、親子の合算予算・共通権限範囲は従来の提案を維持する。
- 既存N-ENDは実行全体の終了要求。並列の一枝を終える操作や、子から結果を返す操作の代用品にしない。標準パレットではN-ENDを主手順の終了位置へ限定し、子ではN-RETURNを使う。

## 6. 保存・実行への変換

### 6.1 正本と補助データ

```text
ブロック／同じ構造の手順一覧
  → 型付きの構造
  → 正規の実行定義（canonical graph）
  → サーバー検証
  → 保存版に固定された実行計画
  → 既存の認可・送信管理を通す実行
```

正規の実行定義を実行の正本とする。UIのJSONをそのまま実行しない。座標、折り畳み、選択は別の表示情報で、実行の順番や枝は正本に含む。ブロックと正式ノードの対応表を持ち、通常表示だけではID・接続・意味を変えない。

| 構造に必要な情報 | 契約 |
|---|---|
| block_id、nodeとの対応 | 安定したID。複製は新ID、名前変更は同じID |
| block_type、登録演算子、schema版 | 許可された種類だけ。未知の種類を実行しない |
| inputs、子の並び、分岐名、次の文 | 型付き。親子・順番・必要入力を明示 |
| 変数・引数・戻り値の参照ID | 範囲、利用時点、型を検証 |
| 子定義の固定版 | 実行時に最新版へ追従しない |
| 実行対象／今回は使わない | 対象から外すこと自体も意味のある変更 |
| 出所・所属・必要権限・保存可否 | サーバーが導出・検証する。クライアントの自己申告を信用しない |

意味のハッシュには種類、値、接続、実行順、条件、内包関係、引数、戻り値、固定版、必要な権限契約を含める。色・座標・折り畳み・選択を除外する。上下の並べ替えは意味の変更であり除外しない。同じ意味の別の作り方が必ず同じハッシュになるとは保証しない。

### 6.2 正式な処理への対応

| ブロック表現 | 対応 |
|---|---|
| 条件値、もし／それ以外／確認できない | N-COND＋N-BRANCH。有限選択はN-SWITCH |
| 変数を作る・値を変える・計算 | N-VARの登録演算子。文字の案内文はN-RENDER |
| 許可先一覧・各項目 | N-LIST＋N-FOREACH |
| n回繰り返す | 新設count_range＋N-FOREACH |
| 時間・イベント・承認待ち | N-WAIT／N-AWAIT／N-APPROVE |
| 状態を確認 | N-READ。受付の作成・解決N-TICKETとは別 |
| 同時に進め、全枝を確認 | N-PARALLEL＋N-JOIN |
| 共通手順を使う・結果を返す | N-CALL／N-RETURN |
| Discordへの送信・ロール等 | 既存N-SEND、N-ROLE等とC-AUTH/C-ACTION。UIから直接送らない |

「もし」1個が内部では複数処理になることを隠さず、試運転と影響確認に「実行される処理の数」を表示する。見えるブロックの数だけで既存上限を判定しない。

### 6.3 API・DB差分（既存スタック未照合の仮契約）

新しい実行基盤やDB製品を前提にしない。既存の下書き保存・検証・試運転・有効化の責務を維持し、次を追加する案である。

- 下書き保存：期待する下書き版、構造、UI補助情報を受ける。未入力・未接続なら問題一覧付きで保存できるが、宣言型違反、壊れた式、他サーバー参照や秘密、未知の実行命令は保存を拒否する。
- 変換・検証：UI構造から許可した正規定義へ変換し、型、出所、到達可能性、変数範囲、認可、承認経路、全体予算、保存条件をサーバーで確認する。
- 試運転：保存版と模擬入力で同じ意味を評価し、ブロックIDに経路・理由・予定操作・不足を対応付ける。本番のRun、承認消費、Discord変更を作らない。
- 有効化：検証・試運転・影響確認が対象とする保存版を一致させる。UI自己申告の「検証済み」は根拠にしない。
- 保存後読込：正規定義、UI対応、下書き版を返す。版競合なら自動で上書き・マージしない。
- 追加の永続Undo履歴、別エンジン、任意コード置場は作らない。新規保存目的・期間が必要になった場合は従来の保持承認へ含める。

### 6.4 旧定義

入れ子へ安全に変換できない旧定義は、ID・接続・設定・型・版を欠落なく保持し、経路を確認できる読み取り詳細を出す。ノードを複製したり、枝を省いたり、順番を変えて見た目だけ合わせない。部分編集の安全性を保証できなければ定義全体を読み取り専用にする。

既に有効な版を、画面へ変換できない理由だけで止めない。ただし実行・安全検証が別途失敗する場合は既存規則に従う。新しい版を有効にするには、完全な変換と検証を満たすか、新しい下書きとして明示的に作り直して差分・影響を確認する。一般線グラフの恒久編集画面へ誘導する旧説明は削除する。

## 7. 未接続・無効化・元に戻す

| 状況 | 扱い |
|---|---|
| 接続していない有効ブロック | 下書き保存可能。有効化不可。自動実行しない |
| 「今回は使わない」へ明示移動 | 保管領域として保存、実行計画から除外。秘密等の保存禁止は継続 |
| 条件・繰り返し全体を無効化 | 内側も無効。中の処理を自動で外へ出さない |
| 必要な承認を削除・無効化 | 操作側の承認要件は残る。承認経路が欠ければ有効化・操作を拒否 |
| 値を作るブロックを無効化 | 後続に依存があればエラー。0・空値で補わない |
| ブロックをクリック | 設定を開く。単独の確認は純粋な値計算または模擬試運転のみ |

Undo/Redoは「編集を戻す／戻した編集をやり直す」。現在タブの同じ下書き内の追加・移動・削除・設定変更を対象にする。一回の挿入や内包移動を一操作として戻し、ID・参照・焦点も復元する。

本番の送信、ロール変更、有効版の切替、実行状態、中止、承認消費は戻さない。意味が変わったら試運転・影響確認を失効させる。以前と同じハッシュへ戻っても古い承認や確認済み状態を無条件に復活させない。

初期案は現在タブ内50操作、合計2MiB以内のメモリ履歴とする。いずれも測定前の可逆的な値で、永続保存期間を追加する提案ではない。上限を超えた古い編集から戻せなくなることを表示する。再読込・ログアウト後は保存済み下書きを読み、Undo履歴は戻さない。別タブ更新は競合として止め、古いUndoで新しい版を上書きしない。

## 8. 有界な実行と保存

個別待機7日以内以外の数値は実測前の提案であり、了承済み・性能保証とは扱わない。公式制限や測定結果の方が厳しければ、小さい上限を適用する。

| 項目 | 引き継ぐ／追加する案 |
|---|---|
| 1定義 | 正規化後50処理、定義256KiB。UI補助情報も別枠256KiB以内として検証する提案 |
| 1実行 | 処理通過200、外部変更25回。全枝・全反復・子手順を合算 |
| 一覧・回数 | 25項目、回数0〜25。開始時固定 |
| 並列・共通手順 | 3枝、呼出し深さ3、再帰なし |
| 条件 | 深さ5・葉20の既存案を維持 |
| 純粋な計算式 | 追加案：1式の深さ8・演算要素64、1実行の演算評価合計1,000 |
| 変数 | 全枝・全呼出しを含む保存値64個・合計16KiB。領域分割で回避しない |
| 文字 | 単一Text 2,000文字案、送信文面1,500文字案。送信先の制限も別に検証 |
| 実行期限 | 全体7日案。待機・呼出し・再開で延長しない |

条件式には条件の厳しい上限を、算術等には式上限を適用し、混在時も両方の制限を検証する。演算カウンターはループ、子、並列、待機後にリセットしない。制御記録の一部として保存が必要なら、既存の未承認保持方針に明示して採用前に決める。新しい長期履歴を正当化しない。

静的に分かる最大経路を有効化前に見積もり、実行時にも予算を消費する。上限を超える構造は拒否する。見積もれない規模を無制限として通さない。制御・式・共通手順の展開後を計上するため、短い見た目で大量送信を隠せない。

## 10. 三つの具体的な組み立て例

### A. 予定時刻に三つのチャンネルへ案内

```text
指定した日時になったら
  送信先を [案内] [イベント] [運営] にする
  送信先の各チャンネルについて
    案内文 [開始のお知らせ] を作る
    現在のチャンネルへ案内を送る
```

正式対応：T-SCHEDULE → N-LIST → N-FOREACH（N-RENDER → N-SEND）。一覧は許可したChannelRefを開始時に固定する。現在の送信権限を各操作直前にも確認する。

試運転では架空の予定時刻と3件の予定送信を表示し、本番送信0件。2件成功後に3件目が確実に失敗なら成功済み2件を保持して残り停止。3件目の結果が不明なら全体を単なる一部完了とせず、既存の結果確認へ進める。再開時に1、2件目を再送しない。

### B. 選択式申請を承認してロールを付ける

```text
申請を受け取ったら
  もし [申請の種類 = イベント参加] なら
    [申請者] に [参加者ロール] を付ける承認を待つ
      承認されたら
        現在の権限と対象を確認する
        申請者に参加者ロールを付ける
      拒否・期限切れ・承認が無効なら
        付けずに終える
  それ以外／必要な情報を確認できない場合
    付けずに理由を示す
```

正式対応：T-FORM → N-COND → N-BRANCH → N-APPROVE → N-READ → N-ROLE。各待機結果は正式な結果経路に対応し、C字形の通常の下端へ無条件に流さない。

申請者の身元は認証済み入力から固定する。入力者が対象者・承認者を自由に差し替えない。承認は対象・ロール・内容・版に結び付ける。承認後に内容や資格が変われば失効する。Botの権限・ロール階層も直前確認する。フォーム、承認記録、ロール付与由来の保持が未承認なら提供を有効にしない。

試運転は承認、拒否、期限切れ、権限失効を切り替え、実ロール変更0件。承認ブロックを外しても操作側の必須承認は消えず、有効化できない。

### C. 未解決の受付だけを翌日に共通手順で案内

```text
受付が作成されたら [受付の参照]
  受付の状態を確認する
  もし [未解決] なら
    24時間待つ
    受付の状態をもう一度確認する
    もし [未解決] なら
      共通手順 [運営へ受付を案内] を使う
        入力：受付の参照、許可した通知先
    解決済みなら案内しない
    状態を確認できなければ案内せず理由を示す

共通手順 [運営へ受付を案内]：固定した版
  許可された情報から固定の案内文を作る
  許可先へ送る
  成功を確認して送信結果の参照を返す
```

親の正式対応：T-INTERNAL(ticket_created, TicketRef) → N-READ → N-COND → N-BRANCH → 未解決ならN-WAIT → N-READ → N-COND → N-BRANCH → なお未解決ならN-CALL。子の中はN-RENDER → N-SEND → 成功確認 → N-RETURN、戻った後に親が正常終了する。N-RETURNより後に子の送信を置かない。

解決済みなら予定通知0件。読取り不能でも通知0件で理由を残す。必要に応じた再確認は明示した有界の読取りだけで、無制限に待たない。待機の終了を受付の解決とみなさず、状態読取りにN-TICKETを使わない。子の送信結果不明は成功の戻り値を作らず、親も既存の結果確認へ移る。受付情報・待機中の最小記録の保持は未承認の提供条件を引き継ぐ。

以上の3例は設計表上で正常・否定・不明・期限・一部成功を追跡したもので、実行して通過した試験ではない。
