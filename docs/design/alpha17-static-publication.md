# alpha17 static publication adapter

This change implements an announcement-only generation pipeline and connects it to the loopback Operator's existing reviewed command and step-up flow. It does not install a publisher for withnexus.net, connect to a host, publish a site, copy legal candidates, or relax alpha16 safety/retention gates.

## Flow and authority

1. The Operator preview reads the exact immutable announcement revision, shows its reconstructed PUBLIC content and captures the current independently verified generation. Publication and withdrawal both require explicit scope/translation confirmation and current global publication permission.
2. Independent authority is observed before taking the DB transaction/global lock; a one-use process-local proof is bound to the exact command and checked synchronously under the lock. The reviewed PUBLIC content hash is also pinned and rechecked at staging. Confirmation consumes the preview/step-up and records only PREPARED state in the same DB transaction. No external write occurs in that transaction. A fresh committed result dispatches once. A replay returns its existing operation without dispatch. A crash after commit is not automatically replayed.
3. `AtomicStaticPublisher` accepts only a host-bound, process-local, finite proof from an isolated functional probe. JSON flags, browser requests and restored files cannot mint the proof. The probe exercises immutable staging/readback, two competing conditional switches, whole-generation route/manifest readback, withdrawal and independently enforced public expiry. All host cache layers must be covered by the concrete adapter's public read implementation. The probe alone does not establish a legal approval or a new retention period.
4. The narrow initial template must exactly reproduce the current host bundle (including its manifest and generated time) before any staging/switch. Existing legal, status, pricing, release or other unhandled content stops with NOT_STARTED instead of being removed by an announcement update. A reviewed adapter to merge those approved public projections is a separate hosting integration step. The pipeline validates the strict public payload/hash and explicit current source root, preserves withdrawal high-water marks, reconstructs a complete public generation and compares the whole site revision. Missing roots do not imply zero. It stages and re-reads the immutable bundle before one conditional switch, then re-reads publicly routed bytes. Legal, private health, drafts, contact details and billing settings are excluded from this exporter.
5. Before a switch is admitted, an error is NOT_STARTED. A switch timeout/lost acknowledgement, or failed public readback after switching, is UNKNOWN. The DB admission fence prevents resend. The Operator's reconciliation endpoint only reads and compares the exact generation/hash, including withdrawal hashes. It cannot send content or retry.
6. Independent publication safety may be read from a proven REMOTE host. LOCAL_FIXTURE proof is rejected as an independent safety source. The remote expiry is preserved; reads do not extend it. Unset deployment options remain closed.

`tests/unit/alpha17-publication.test.ts` uses a local in-memory host with a single atomic root pointer, immutable staging and no cache. Those results cover the pipeline and that fixture only. They are not evidence of Onamae/FTP atomic switching, CDN invalidation or PC-off expiry behavior.

## External hosting prerequisites

The real deployment still needs the exact hosting plan, FTPS/SFTP endpoint and host/certificate pin, approved public root, separately proven private staging root, existing-site backup, and reviewed artifact manifest digest. A saved session is referenced without reading its credential contents. Plain FTP and disabled certificate/host checks are not supported.

The host must provide a conditional atomic switch of all public routes, the index and manifest through one root; immutable upload alone does not suffice. It must independently reject expired routes while the PC is off, keep finite withdrawal/generation safety roots, and establish uncached readback across every relevant proxy/CDN layer. No such adapter is installed. `UnverifiedHostingPublisher` reports NOT_STARTED and makes no I/O. WinSCP staging is a separate capability and never claims publication success. A sequential overwrite of files is not an implementation of this contract.

Before enabling real publication, implement and review the concrete host routing/switch/expiry adapter, verify its isolated namespace is disjoint from the live site, exercise its behavior, approve canonical origins and retention enforcement, and provision the independent current source roots by a reviewed bootstrap procedure. Do not bootstrap zero from an absent host row. With no atomic server-side primitive, stop before public switch and select another hosting mechanism.

The legacy offline builder remains available for explicit manually reviewed public input. Its APPROVED_PUBLIC literals are schema markers, not legal approval evidence. It must not be fed local legal candidate files or personal contacts without separate approval and artifact review.
