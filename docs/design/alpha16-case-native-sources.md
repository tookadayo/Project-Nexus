## Immutable SQL observation and retention

`case-metric-observations.ts` captures each new bounded SQL observation once in 082 `rule_case_metric_observations` and typed `rule_case_metric_values`. This is the existing evaluation-source purpose. A header stores only context/config/source hashes and clocks; values use scalar/cohort columns. JSON is limited to typed period/cohort/metric metadata. No actor/member list, message body or arbitrary business-value JSON is saved. At most 12 fields per observation and 64 retained observation versions per context are accepted; raw native result populations are bounded at 200,000, with an overflow sentinel that fails closed.

The key includes the native recommendation target **and**, when present, the separate server-derived base program `rootTarget`. Current program revision/content and exact event/channel membership enter the source hash. The common CASE context and pipeline separately seal the current base Rule result's program target/window/hash; `ruleTargets` remains the native program and `caseTargets` contains the actual event. The pipeline never aliases a program UUID to an event ID.

First capture uses the authoritative capture asOf as the new SQL observation clock. Business windows, native ingest clocks and native configuration identities remain separate. Expiry is the earliest of capture +48h, the already validated parent ceiling, existing parent expiry, native retained-detail expiry, source configuration expiry and current visibility ceiling. The DB enforces the 48-hour header maximum. Later reads recompute against the original capture asOf, compare source/value/binding hashes and return the original clock/expiry; they cannot create a missing source or refresh its lifetime. New current source ceilings can only shorten validity. Saved calendar boundary instants are reused on validation; only a fresh source capture resolves the explicit IANA full-day boundary, including DST.

082 child EAV → header → 077 context is the deletion order (both relationships cascade; the header-to-context FK is deferred for same-transaction first capture). Source expiry/purge hooks delete headers and cascade children. Actor deletion conservatively purges every 082 source in the scope because these aggregate snapshots do not retain a subject-membership list proving independence. The common owner removes affected source descriptors/typed fields and cancels affected pending jobs before native subject erasure. This introduces no independent retention purpose and does not change native source retention.

## Genuine unavailable semantics

- No subject-bound welcome no-contact preference is supplied by this shared resource source. No asker-confirmed solution, explicit unclear/clear outcome, voluntary interest or individual format preference is collected or inferred.
- CASE03/04's current mandatory HELP-001 root names HELP_INTAKE_POLICY (source configuration UUID). Native Discord issues name attention/message snowflakes. Existing intake `attention_key='intake:'+requestId` has no authoritative Discord message reference; INTAKE_NOTIFY does not persist a corresponding published message mapping. The source rejects arbitrary policy-to-issue staff mappings. Its canonical native reader exists, but this root/resource relation is unavailable. RESOLVED, ACK and IN_PROGRESS do not repair the missing asker-outcome/first-response source.

- Legacy Bot/mention/schedule metadata, erased reply provenance, expired detail, collection gaps, missing role/member eligibility and unsupported event formats remain UNKNOWN. Profile enablement cannot fabricate them.
