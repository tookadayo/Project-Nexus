# Alpha17 private staging transport

Design and safety contract before transfer implementation:

- Input is one immutable `generation-N` directory produced by the offline official static builder, plus a strict non-secret transport config. The config pins the exact reviewed manifest SHA-256, review reference and expiry. Approval must cover legal/contact text and any personal information. A filename allowlist or a content scanner cannot provide that approval.
- Inspect every manifest entry, actual directory/file set, file SHA-256, asset filename hash and UTF-8 encoding. Reject unlisted files/directories, aliases, symlinks, hard links, oversized files and typical private-key/credential material. Only the official builder's concrete public HTML/CSS/JS/JSON paths are accepted. Next output, API, DB, private candidates, logs, backups, environment files and the source tree are excluded.
- WinSCP uses an existing dedicated read-only, protected INI and a saved site reference. This code stats that file but never reads, copies, exports or prints it. Credential creation, protection and runtime account setup are separate operator work. Both `WinSCP.com` and its sibling `WinSCP.exe` have pinned hashes; official signature verification is an installation prerequisite.
- Force the separately reviewed host/port and SFTP-only with the SSH SHA-256 fingerprint. FTPS is unconditionally **NOT_STARTED/STAGING_FTPS_STRICT_PIN_UNAVAILABLE**, including with an injected runner: WinSCP's `-certificate` is a trust exception and does not force fingerprint comparison when CA/hostname validation already passes. No FTPS transfer receipt can be issued. A separate strict-pin transport is required if hosting only supports FTPS. No plaintext FTP, implicit FTPS, wildcard/accept-new identity, local proxy command, custom SFTP command, agent forwarding or bypassed authentication. Missing credentials cancel rather than prompt or open a GUI.
- A separate, current host/provider verifier must establish the canonical staging root is non-public, not an alias/symlink into ANY public root, writable/readable by the intended account and supports fail-if-present directory creation. It returns a short-lived proof bound to the exact host/port/protocol/identity/root/document-root set. The transport does not treat JSON booleans as this proof. **No such real-host verifier is installed yet, so the shipped CLI cannot start a connection.**
- After authorization, snapshot only the reviewed bytes in a temporary local directory. Create one random, new remote generation directory strictly below the private root. `mkdir` failure aborts; never reuse, retry or clean an uncertain remote directory. Upload exact files in binary mode with resume disabled, then download every file and independently recheck the full manifest and hashes. A native runner must pipe commands through stdin, discard child stdout/stderr and retain no logs; the script plan directs WinSCP logs to the null device. Passwords/tokens never enter config, argv, script, application output or retained logs.
- **No native runner is integrated into real staging.** The SFTP default remains `NOT_STARTED/STAGING_NATIVE_RUNNER_UNVERIFIED`. A separate [Windows Job helper](alpha17-windows-job.md) is now implemented and passes 13 local synthetic tests, including timeout/EOF/tree cleanup, image/hash/path locks and bounded input. This does not register host verification or real WinSCP credentials, pins, binary capabilities or a production staging binding. PID-only `taskkill` is not an acceptable ownership proof. Staging unit tests still inject fake runners and make no server connection.
- Only a successful runner AND complete matching readback yields `STAGED_VERIFIED, published:false`. Once a runner is admitted, any error, timeout, missing/changed readback or throw yields `UNKNOWN, published:false`; do not repeat that attempt or claim the process has stopped. The receipt's random staging ID identifies the quarantined directory. Local reviewed-public scratch is removed after the attempt.
- This transport does not implement `StaticPublisher`, switch generations, change active routes, update pointers, delete files, change permissions, or write a live document root. A verified staging receipt proves only staging bytes. Atomic generation comparison/switch, route withdrawal, cache behavior and independent safety state require a separate host-verified publisher adapter. Sequential FTP overwrites cannot satisfy that contract.

API: `inspectOfficialBundle({config,bundleDirectory})` is a read-only local preflight. `stageOfficialBundle(input,{authorizePrivateRoot,runner?,now?})` requires the verifier and reviewed runner above. Both are fakes in unit tests; tests never connect to a server. A native runner must satisfy the owned-process-tree and credential/output boundaries before later integration.

The CLI `corepack pnpm exec tsx scripts/publication/stage.ts <config.json> <generation-directory>` only preflights. Its optional `--execute-staging` remains `NOT_STARTED/STAGING_PRIVATE_ROOT_UNVERIFIED` until provider-specific verification is implemented. Keep configs/session stores outside source and launch-entry folders; never paste credentials into command arguments or chat. No sample credentials or ready-to-use remote configuration is supplied.

WinSCP implementation references: [stdin and noninteractive command line](https://winscp.net/eng/docs/commandline), [saved-site open and pinned identity](https://winscp.net/eng/docs/scriptcommand_open), [batch abort and overwrite confirmation](https://winscp.net/eng/docs/scriptcommand_option), [binary upload and resume settings](https://winscp.net/eng/docs/scriptcommand_put), [read-only isolated INI](https://winscp.net/eng/docs/scripting), [protocol enums](https://github.com/winscp/winscp/blob/master/source/core/SessionData.h), [CA-valid FTPS verification path](https://github.com/winscp/winscp/blob/master/source/core/FtpFileSystem.cpp). The supported executable version/hashes must be reviewed against those settings before enabling a real verifier.


Regression verification: the FTPS rejection precedes local-tool/session validation, private-root verification and any runner call. A test injects the exact `WindowsJobRequest -> WindowsJobResult` function shape (including `treeTerminated:true`) and verifies `NOT_STARTED/STAGING_FTPS_STRICT_PIN_UNAVAILABLE` with neither verifier nor runner invoked. Process containment does not confer TLS certificate-pin authority. No real host, credentials or native process is used in this test.
