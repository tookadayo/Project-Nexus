付録I-A：全機能対応表
A-0. 適用範囲

本付録は、alpha16の全機能をA配置へ対応させるための追跡表である。

A配置は承認済みの配置方針であるが、実装承認ではない。

お名前.com：静的公式Web

Windows PC：Next.js Dashboard / BFF / 全動的サーバー処理 / Worker / Scheduler / DB等

app サブドメイン → Cloudflare Tunnel → Windows PC

Browser → same-origin Next.js BFF

Browser → PC API / DB の直接接続は禁止

BFF → 内部PC APIは署名付き

guild・権限は必ずserver側で再検査

Discord Gateway / RESTはPCからDiscordへの外向き通信であり、Tunnelを経由しない

Operatorはloopback限定で、Tunnel・公開Webへ絶対に公開しない

A配置だけを理由として、Next.jsのserver-side DB readを全面的にAPI bridge化しない

RESULT_UNKNOWN の外部副作用は自動再送しない

Run終了後の最小状態は7日以内に削除

backup保持は7日

30日、24か月等の延長保持値は採用しない

PC停止、Tunnel断、Worker停止、PC外向き通信断、Discord応答喪失は別状態として扱う

alpha16実装完了後に全体動作確認・修正・受入をまとめて実施する

本付録作成時点では実装・設定変更・試験・修正を行わない

A-1. 共通契約
A-1-1. 状態表記

全Dashboard系画面は原則として以下の共通状態を使用する。

コード	状態	UI契約
S	Success	現在取得できた値を表示
E	Empty	正常な「対象なし」。エラーとは表示しない
L	Loading	初回取得中。未取得値を推測表示しない
T	Stale	取得済みだが鮮度契約を満たさない。最終更新時刻を表示
C	Conflict	version不一致等。黙って上書きせず再取得を促す
U-PC	PC停止/不可到達	Dashboard/BFF自体が到達不能になり得るA案固有状態
U-TUNNEL	Tunnel断	PCは稼働していてもappへ到達不能
U-WORKER	Worker停止	Web/BFFは使用可能だが処理実行不可
U-OUT	PC外向き通信断	DB等は使用可能でもDiscord/Stripe等外部処理不可
U-EXT	外部応答喪失	外部副作用の結果が確認できない場合を含む
F	Failure	既知の処理失敗。安全な再試行可否を明示

Tは「正常」と同じ表示にしない。特にStatusについてはvalidUntilを過ぎたsnapshotを正常状態として表示しない。

A-1-2. 認可共通契約

すべての認証済み操作は概ね、

session → guild選択 → guild所属/対象確認 → permission → 対象version/状態 → 操作

の順にserver側で再検査する。

Browserから送信されたguild ID・role・permission・対象versionを信用しない。

A-1-3. Web境界
境界	契約
公開Web	お名前.com静的配信物のみ
Dashboard	PC上Next.js
Browser→BFF	same-origin HTTPS
Browser→PC API	禁止
Browser→DB	禁止
BFF→PC API	内部署名付き。秘密はBrowserへ返さない
Next server→DB	A配置では既存server-side read/writeを維持可能
Operator	loopbackのみ
Discord	PC→Discord outbound。Tunnel非経由
Stripe	PC上Next/BFFから外部接続

session cookieはhost-onlyとし、提案として__Host-系cookieを利用できる。Domainは設定しない。Secure、HttpOnlyを必須とし、SameSiteは実際のサイト構成に合わせてLax等を採用する。same-originであっても状態変更BFFではCSRF対策を行う。

A-4. alpha16で特に固定する全機能横断境界
1. Suggestionの責務境界

SuggestionはAutomation専用ではない。

対象は、

Automation

Analytics

Explore

Operations

Events

Playbook

Reports

Organization/Teams

その他alpha16で変更可能なNEXUS機能

を含む。

対象識別はautomationIdだけに依存せず、次回のAPI/DB付録で定義するtargetType / targetId / targetVersion体系へ統一する。

Suggestionは、

自動適用しない

自動有効化しない

自動課金しない

自動投稿しない

自動権限変更しない

外部操作を勝手に実行しない

を固定する。

2. RESULT_UNKNOWN

外部副作用を実行した後に結果確認ができなかった場合、

UNKNOWN → 自動再送

は禁止。

照合は副作用を発生させないread-only確認だけを使用する。

照合不能ならUNKNOWNを維持する。

人間が明示的に新しい操作を行う場合も、元のUNKNOWNを成功/失敗へ書き換えず、別operationとして記録する。

3. A配置におけるDBアクセス

A配置ではNext.jsそのものがWindows PC上にある。

したがって、

Browser → Tunnel → Next.js BFF → server-side DB

という経路は許容する。

Explore/Operations等の既存server-side DB readについて、Tunnel対応だけを理由に、

Next.js → PC API → DB

へ全面的に書き換えることはalpha16の必須条件ではない。

一方、Browserへ直接DB情報を出す設計変更は不可。

A-5. 現時点での実装着手境界

実装担当者は、上表を根拠として以下を勝手に変更してはならない。

A配置をB配置へ変更しない。

Browser直結APIを追加しない。

DBをBrowserへ公開しない。

OperatorをTunnelへ公開しない。

Discord Gateway/RESTをTunnel経由へ変更しない。

server-side DB readをTunnel対応だけを理由に全面bridge化しない。

RESULT_UNKNOWNを自動retry可能へ緩和しない。

Suggestionから自動適用を実装しない。

未承認の保持期間を追加しない。

minN、信頼度、統計的独立性等を勝手に保証値として扱わない。

現在存在するroute/table名を推測で新規契約名として確定しない。

未公開のLegal/Statusや無効なContactを完成済みとして扱わない。
