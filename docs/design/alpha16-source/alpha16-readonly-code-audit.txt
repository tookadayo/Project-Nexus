通信設定の入口はあります。`NEXUS_API_URL`でAPI接続先、`NEXUS_WEB_URL`で正式origin・OAuth callbackを指定できます。ただし、現在の基本経路は **ブラウザー→同一originのNext BFF→署名付きPC API** です。変更操作はOrigin／Host／Fetch-Siteを検証し、API本人証明もサーバー側で生成します。ブラウザーから別originのPC APIへ直接接続するCORS・Cookie構成は、現契約のままでは対応しません。[URL設定](<D:/Project Nexus/apps/web/app/auth/session.ts:193>)、[CSRF境界](<D:/Project Nexus/apps/web/app/auth/origin.ts:2>)

追加設計の中心は、**静的配信とNext実行の分担、Web直接DB処理のAPI化、認証・公開route境界、停止中の表示方針**です。PC停止時はAPI・分析・Discord処理・予定実行が止まります。Webにはタイムアウト／失敗表示がありますが、認証もDBに依存し、停止中に全画面や最終提案を閲覧できる独立キャッシュはありません。[失敗処理](<D:/Project Nexus/apps/web/app/dashboard-data.tsx:43>)
