19. なぜSSEだけにしないのか

SSEは、

38. 最終判定
現在のalpha15設計は、この構成に対応できるか？

→ できます。ただし「そのまま」ではなく、alpha16でWeb/APIの配置境界を正式に更新する必要があります。

特に既存設計の

Windows上の動的Web/API

という部分を、

レンタルサーバー上の静的Web + Windows PC上のAPI

へ変更するのが最大の設計変更です。

一方、

canonical graph
server validation
fixed Revision
Run checkpoint
Scheduler
Wait
7日期限
external result unknown
guild authorization
draft / active revision分離
試運転
外部操作の承認

といったNEXUSの本質的な実行契約はほぼそのまま利用できます。

そしてalpha16で新たに、

Rule EngineはWindows PCで動くread/analysis中心のサービスであり、Suggestionを生成するだけ。WebはSuggestionを表示するだけ。SuggestionはAutomationを直接変更・有効化・実行できない。

という境界を追加すれば、以前の「AIが管理者の制御を奪わない」という方針とも綺麗に接続できます。

また、SSEは採用してもよいが正本にはせず、Pollingを必ずフォールバックとして残すのが最も堅牢です。

なお、TunnelはPCとWebサーバーを直接接続するものではなく、Cloudflareを介したブラウザー→Windows PC APIの公開経路として定義するのが正確です。
