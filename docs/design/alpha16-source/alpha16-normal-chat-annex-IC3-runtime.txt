2. Run/Step/Wait/Schedule差分

Runへflow_revision_id immutable、state_version、terminal_at、UNKNOWN期限。Stepへstep_revision、state_version、operation_intent_id、resume_at、固定乱数。Waitは期限付きresumeを保持し再開直前にtombstone/permission/plan/revision有効性を再確認。Rollbackは新revisionのみで既存Run不変。Scheduleはplanned fire/materialized Run/schedule revisionを区別、missed=SKIP。

3. 状態遷移
from→to	actor / 前提	同transaction	副作用 / 回復
JOB Q→CLAIMED→RUNNING	Worker+lease	job+lease	内部jobのみexpiry後requeue
RUN READY→RUNNING	Worker/Scheduler、認可+tombstone	Run+Step+outbox	revision不変
STEP RUNNING→WAITING	Worker、wait成立	Step+resume+outbox	dueで再開
INTENT READY→CLAIMED	Worker+fence	Attempt+lease	admission前cancel可
CLAIMED→EXECUTING	fence一致、target/live/draft/version再確認	admission commit	commit後のみ外部call
CLAIMED→CANCELLED	User/Worker、admission未commit	Intent+Attempt	無副作用
EXECUTING→SUCCEEDED	Worker、成功確認	Result+Attempt+Intent+Run/Step	後続queue
EXECUTING→FAILED_PRE_EFFECT	Worker、admission前の無効果確定	Attempt+Intent	条件時のみ再attempt
EXECUTING→RESULT_UNKNOWN	Recovery/Worker、admission後不明	UNKNOWNをResult+Intent/Runへ	同一副作用自動再送禁止
EXECUTING→CANCEL_REQUESTED→UNKNOWN	admission後・応答なし	Intent+Attempt	取消確約不可
UNKNOWN→CONFIRMED_SUCCESS/NO_EFFECT	read-only reconcile	Result+Intent CAS	不能なら維持
UNKNOWN→terminal	deadline	terminal_at	FAILEDへ偽装せず再実行不可

send admissionのDB commitが線形化点。commit前のcancel/lease expiryなら送信不可、commit後は取消確約不可。Discordはfenceを検査しないためexactly-onceは保証せず、fenceは旧Workerの更新/admission拒否に使う。

4. crash/recovery

intent前=未commitなら無効果。intent後/queue前=PG+outboxから再構成。claim後・admission前のlease expiry=pre-effect。admission後のPC/Worker停止、外部送信前後、response前後、result commit前=UNKNOWN。commit後はPGから再開。PC outbound断もadmission後はUNKNOWN、前に無効果確定ならpre-effect。Discord応答喪失=UNKNOWN。Tunnel断単独はUNKNOWN原因にしない。UNKNOWN再queue禁止、reconcileはread-only。

5. Apply reservation / tombstone

同一guild+suggestion+immutableDraftRevisionに加え、異なるSuggestion/draftでも同一guild+target+approved_live_target_versionの有効予約を一件に制限する。成功でlive版が進み並行側はCAS競合。UNKNOWNはreservation保持、確実なpre-effect失敗だけ解除可。CONSUMEDは成功確定のみ。tombstoneはclaim/resume/admissionより優先し、restore後もtombstone再適用。

lock順=Run/Step→Intent→Attempt→Lease。queueはoutbox commit後にIntentを取得し逆順lockしない。更新はstate_version/fence CAS、重複はunique。受入はalpha16実装完了後に一括。
